💡 الفكرة

الويب = مستندات مربوطة ببعض بروابط

World Wide Web نظام لنشر المستندات والوصول ليها عبر الإنترنت، والمستندات فيه مربوطة ببعض بـ روابط (Hyperlinks).

🔗 الربط

تضغط على رابط في مستند ← يفتح مستند تاني، حتى لو على جهاز في بلد تانية.

📤 تبادل المعلومات

أي حد ينشر مستند مرة واحدة ← أي حد عنده متصفح يقدر يوصله.

⚠️
الويب مش هو الإنترنت. الإنترنت هو الشبكة اللي بتوصّل الأجهزة (موجودة قبل الويب). الويب خدمة شغالة فوق الإنترنت، زي ما الإيميل خدمة تانية فوقها.

📅 سنة 1990 اشتغل أول Web Server وأول متصفح، وسنة 1991 الويب بقى متاح للناس برّه CERN.

السيرفر بيبعت… والمتصفح بيفهم ويعرض

🗄️ Web Server

  • يستقبل الطلب.
  • يحدد المورد المطلوب.
  • يبعته كما هو في الرد.

ميهموش الصفحة شكلها إيه على الشاشة.

🖥️ Web Browser

  • يقرا HTML ويحلّله.
  • يبني منه تمثيل داخلي للمستند.
  • يرسم المحتوى على الشاشة.

لو الصفحة محتاجة صور أو ملفات تانية، يبعت لها طلبات إضافية.

💡
السيرفر بيبعت نص HTML، مش "صورة للصفحة". المتصفح هو اللي بيحوّل النص ده لصفحة تقدر تشوفها.

Dynamic Web Page و SSR

Dynamic Web Page · صفحة ديناميكية صفحة محتواها بيتولّد وقت الطلب، حسب مين طلبها أو حسب البيانات الحالية.
Server-Side Rendering (SSR) إن السيرفر هو اللي يجهّز HTML كامل (قالب + بيانات) قبل ما يبعته للمتصفح.
📄 Static⚙️ Dynamic (SSR)
المحتوى بيتجهز إمتى؟مسبقًا، مرة واحدةوقت كل طلب
السيرفر بيعمل إيه؟يلاقي الملف ويبعتهيشغّل Backend، يجيب بيانات، يملا القالب
كل الزوار يشوفوا؟نفس المحتوىممكن كل واحد يشوف محتوى مختلف
محتاج Database؟لأغالبًا أيوه

الـ Backend والصفحات الديناميكية

🖱️ نقلة جديدة🎯 تعرف دور JavaScript

من صفحة بتعرض… لصفحة بتتفاعل

😐 قبل JavaScript

الصفحة بعد ما تتعرض كانت زي مستند: تقراه وتضغط روابط. مفيش كود جوه المتصفح يرد على اللي بتعمله في الصفحة نفسها.

🙂 مع JavaScript

لغة برمجة بتشتغل جوه المتصفح، تخلّي الصفحة ترد على المستخدم: ضغطة زرار، كتابة في خانة، اختيار من قائمة.

✅
تتحقق من المدخلات وتنبّهك فورًا.
👆
تفتح/تقفل قائمة لما تضغط زرار.
🔄
تغيّر جزء من الصفحة حسب اختيارك.

📅 ظهرت سنة 1995 في متصفح Netscape، علشان تضيف سلوك للصفحات جوه المتصفح.

🧱🎨⚡ ثلاث طبقات

استعلام عن النتيجة

شغّل وطفّي CSS و JavaScript، وجرّب تكتب حروف بدل أرقام.

HTML · البنيةإيه اللي في الصفحة: عنوان، خانة، زرار.
CSS · المظهرشكله إيه: ألوان، مسافات، خطوط، ترتيب.
JavaScript · السلوكبيعمل إيه لما المستخدم يتفاعل.

🔄 بتوصل إزاي؟

السيرفر بيبعت ملفات JavaScript مع الصفحة، والمتصفح هو اللي بيشغّلها على جهاز المستخدم.

🤝 علاقتها بـ HTML و CSS

JavaScript تقدر تقرا وتغيّر محتوى الصفحة وشكلها بعد ما اتعرضت: تضيف نص، تخفي عنصر، تغيّر لون.

🔐
التحقق في المتصفح للراحة (تنبيه سريع). لكن الـ Backend لازم يتحقق تاني، لأن أي حد ممكن يتحكم في الكود اللي شغال على جهازه.

Asynchronous Requests و AJAX

Asynchronous Request · طلب غير متزامن طلب بيتبعت والصفحة مش بتقف تستناه: المستخدم يكمل شغله، ولما الرد يوصل الكود يتعامل معاه.
AJAX · Asynchronous JavaScript and XML أسلوب تاريخي ومشهور: JavaScript تبعت طلبات غير متزامنة وتحدّث أجزاء من الصفحة. الاسم انتشر سنة 2005، ومواقع زي Gmail و Google Maps كانت أشهر أمثلته.
ℹ️
رغم إن في الاسم XML، البيانات اللي بترجع مش لازم تكون XML.
⚠️
تحديث جزء من الصفحة ≠ إعادة تحميل الصفحة. مستند HTML الأصلي فاضل زي ما هو، واتغيّر فيه جزء.

🔌 مصطلح

API · Application Programming Interface

التعريف واجهة (عقد) بتحدد البرامج تتعامل مع بعض إزاي: العمليات أو البيانات اللي ممكن تتطلب، وإزاي تتطلب، وإيه اللي هيرجع، حسب القواعد اللي الواجهة بتوفرها.

📘 مثال: API نتائج الجامعة

🌍 أوسع من الويب

برنامج بيطلب من نظام التشغيل يحفظ ملف ← بيستخدم API نظام التشغيل.

📅 أقدم من JavaScript

فكرة الـ API موجودة في البرمجة من قبل JavaScript بسنين. الويب استخدمها، مش اخترعها.

🚫 أخطاء شائعة

الـ API مش…

✗
هي الطلب نفسه. الطلب حاجة بتتبعت حسب قواعد الـ API.
✗
صيغة بيانات زي JSON. JSON طريقة لكتابة البيانات، مش الاتفاق.
✗
لازم تكون REST. REST أسلوب واحد من أساليب كتير.
✗
ردّها لازم يكون JSON. ممكن نص، أو HTML، أو XML، أو غيره.
✗
حاجة خاصة بـ JavaScript أو ظهرت بسببها. أي برنامج بأي لغة ممكن يستخدم API أو يوفّرها.

⚖️ مقارنة🎯 تفرّق بين الصفحة والتطبيق

Web Page ولا Web App؟

📄 Web Page

هدفها الأساسي عرض معلومات. بتقرا وتتنقل.

مثال: صفحة الجامعة: الكليات، العنوان، الأخبار.

🧰 Web App

بتوفر وظائف تفاعلية تخلّيك تنفّذ مهام.

مثال: بوابة الطلاب: تسجّل دخول، تشوف درجاتك، تسجّل مواد، تقدّم طلب.

الفرق مش حد فاصل، هو أقرب لمسطرة:

مقالقراءة بس
صفحة الجامعة+ قائمة تفتح وتقفل
صفحة أخبار+ بحث وتعليقات
بوابة الطلابدخول ودرجات وطلبات
محرر مستندات أونلاينمهام كاملة
📄 أقرب لـ Web Pageأقرب لـ Web App 🧰

الصفحة ممكن يبقى فيها تفاعل، والتطبيق ممكن يتكوّن من صفحات كتير.

ℹ️

📄 صفحات ثابتة

مستندات مربوطة بروابط.

المشكلة: نفس المحتوى للكل.

🗃️ + Database

البيانات منظمة في مكان واحد.

المشكلة: مين يحوّلها لصفحة؟

⚙️ + Backend (SSR)

قالب واحد + بيانات = صفحة لكل مستخدم.

المشكلة: الصفحة مش بتتفاعل.

🖱️ + JavaScript

الصفحة ترد على المستخدم.

المشكلة: أي بيانات جديدة = صفحة كاملة.

⚡ + طلبات في الخلفية و API

نجيب البيانات بس ونحدّث جزء.

النتيجة: Web Apps.
